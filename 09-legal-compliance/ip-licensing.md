## 🎯 Policy Overview

### The "Civic Open Source Default" Principle

**All projects created for civic challenges at Hack for RVA default to open source licensing to enable City of Richmond implementation and public benefit.**

This policy solves the "Valley of Death" problem where hackathon projects cannot be adopted by government due to unclear intellectual property ownership.

---

## 📜 Default Licensing Framework

### For Civic Challenge Projects

**Projects submitted to civic challenge categories automatically license their work as:**

**Option 1: MIT License** (Recommended)
- Simple, permissive open source license
- Allows City to use, modify, and distribute
- Minimal restrictions and obligations
- Industry standard for civic tech

**Option 2: BSD 3-Clause License**
- Similar to MIT with additional attribution requirements
- Prevents use of contributor names for endorsement
- Also widely accepted for civic projects

**Participants choose MIT or BSD at submission time.**

### What This Means

✅ **City of Richmond can:**
- Use the solution for public benefit
- Modify and adapt for Richmond's needs
- Deploy without licensing fees
- Maintain and update over time
- Share with other cities (optional)

✅ **Project creators retain:**
- Attribution (credit for their work)
- Right to use in their portfolio
- Ability to build commercial versions (with different licensing)
- Pride of civic contribution

❌ **City cannot:**
- Claim they created the solution
- Remove attribution from original creators
- Use contributors' names for endorsement without permission

## 💼 Participant IP Rights

### You Own Your Work

**Participants retain ownership of their intellectual property** subject to the open source license they select.

This means:

✅ **You can:**
- Add this project to your portfolio
- Use it in job applications or presentations
- Fork it and create commercial versions (under different license)
- Continue developing it after the event
- Receive credit and attribution

❌ **You cannot:**
- Remove the open source license after submission
- Prevent the City from using the civic solution
- Charge the City licensing fees for the civic version
- Claim sole ownership if you had teammates

### Team Projects

For team submissions:
- All team members are co-contributors
- All must agree to the open source license
- Attribution includes all team member names
- Teams should decide ownership shares in advance if planning commercial versions

## 🏛️ City of Richmond Rights

### Implementation Rights

By accepting civic challenge submissions, the City of Richmond receives:

1. **Right to Use:** Deploy solution for public benefit
2. **Right to Modify:** Adapt for Richmond's specific needs
3. **Right to Maintain:** Update and improve over time
4. **Right to Share:** Publish code for other cities (optional)

### City Obligations

The City of Richmond agrees to:

1. **Provide Attribution:** Credit original creators publicly
2. **Maintain Open Source:** Keep civic versions open source
3. **Document Usage:** Report if/how solution is implemented
4. **Offer Support:** Provide implementation support through Task Force

### City Does NOT Acquire

❌ Exclusive rights (others can use the same solution)  
❌ Commercial rights (creators can commercialize separately)  
❌ Rights to non-civic applications of the technology  
❌ Ability to patent civic solutions

## 🎨 Design, Data, and Non-Code IP

### This Policy Covers All Project Components

**Code:** Covered under MIT/BSD license

**Design Assets:**
- UI/UX designs
- Graphics and visual elements
- Logos and branding
- Released under Creative Commons Attribution (CC BY 4.0) or same as code

**Data:**
- Original datasets created by teams
- Released under Open Database License (ODbL) or public domain
- Note: City data remains City property

**Documentation:**
- User guides, technical documentation
- Released under Creative Commons Attribution (CC BY 4.0)

## 🛡️ Third-Party Tools & APIs

### Using External Services

Teams may use:
- Cloud hosting (AWS, Azure, Google Cloud)
- Third-party APIs (Twilio, Stripe, etc.)
- Open source libraries and frameworks
- Proprietary tools with appropriate licenses

**Requirements:**
- Comply with all terms of service
- Don't violate API rate limits or usage terms
- Give proper attribution to open source dependencies
- Document all external dependencies

### Sponsored APIs & Tools

Sponsors may provide:
- API credits for hackathon use
- Platform access during event
- Post-event credits for winners

**Clarification:** Using a sponsor's API doesn't transfer IP to the sponsor. Your civic solution remains yours under open source license.

## 🚫 Prohibited Uses

### Projects May NOT:

❌ Violate any laws or regulations  
❌ Infringe on others' intellectual property  
❌ Include malicious code, malware, or security exploits  
❌ Collect personal data without consent or appropriate security  
❌ Violate terms of service of platforms or APIs used  
❌ Include plagiarized content  
❌ Discriminate or promote harmful content

### If Prohibited Content Is Found:

- Project will be disqualified from prizes
- Participants may be removed from event
- Reported to appropriate authorities if illegal

## 🏆 Prizes & Commercial Rights

### Non-Civic Projects

Projects NOT submitted to civic challenges (if any general categories exist):
- Participants choose their own licensing
- Can be proprietary, commercial, or open source
- Not required to use MIT/BSD

### Prize Eligibility

To be eligible for civic challenge prizes, projects must:
- ✅ Be submitted to a civic challenge category
- ✅ Use MIT or BSD open source license
- ✅ Have all team members agree to license
- ✅ Include proper attribution documentation

### After Winning

**You can:**
- Build commercial versions with different licensing
- Start companies based on the technology
- Seek venture funding or grants
- Use in your portfolio and resume

**The civic version must remain open source.**

Example: You build a Tree Equity Dashboard. The civic version for Richmond stays open source (MIT). You can create a commercial SaaS version for landscaping companies under proprietary license.

All civic challenge projects must include:

2. **README.md** with attribution of all contributors
3. **CONTRIBUTORS.md** listing all team members
4. **IP Declaration Form** signed by all team members [Template TBD]

### IP Declaration Form Contents

Each team member must sign declaring:
- I contributed to this project
- I agree to release under [MIT/BSD] license

- I used no proprietary code I don't have rights to

## 🌍 Exceptions & Special Cases

### Non-Civic Projects
If Hack for RVA adds non-civic challenge categories, those projects may use any licensing. Open source not required.

### Pre-Existing IP
If teams build on their own pre-existing projects:
- Pre-existing code can remain under original license
- New contributions for civic challenge must be MIT/BSD
- Clear documentation of what's pre-existing vs. new

### Proprietary Components
If a solution includes proprietary components (sponsor APIs, commercial tools):
- Document clearly in README
- Provide open source alternatives if possible
- Ensure City can deploy without proprietary dependencies
- Or provide free/low-cost licensing for City use
